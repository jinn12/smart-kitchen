# 서비스 기획서 — Smart Kitchen (가칭)

- 버전: v0.1 (초안) / 작성일: 2026-07-31 / 상태: 검토 중
- 관련 문서: [Decision Log](./decisions/decision-log.md) · 후속: 용어 정의서 → IA → 도메인 모델 정의서 → ERD

---

## 1. 한 줄 정의

냉장고 재고를 중심으로 **요리 → 식탁(식사 계획) → 장보기**가 자동으로 순환하는 식재료·식사 관리 모바일 앱.

## 2. 문제 정의

- 냉장고에 무엇이 있는지 모른 채 장을 봐서 **중복 구매**와 **식재료 폐기**가 반복된다.
- 기존 재고 관리 앱은 "입력은 귀찮은데 다시 열어볼 이유가 없어서" 실패한다. 기록 도구에 그칠 뿐 장보기·식사 준비라는 실제 행동과 연결되지 않는다.
- 식사 계획, 재고, 장보기 목록이 각각 따로 놀아 사용자가 머릿속으로 대조해야 한다.

## 3. 타겟 사용자

| 구분 | 대상 | 특성 |
| :---- | :---- | :---- |
| 1차 (MVP) | 30~40대 주부 (D-001) | 재고 규모가 크고, 주 1회 대량 장보기, 반복 메뉴 다수. 가족 단위 식사 준비 |
| 2차 (로드맵) | 1인 가구 직장인 | "사놓고 썩힘"이 핵심 고통. 요리 빈도 낮음 — MVP 검증 후 재검토 |

## 4. 핵심 컨셉 — 순환 구조

```
냉장고(재고) ──▶ 요리(레시피) ──▶ 식탁(식사 계획)
    ▲                                   │
    └────── 장보기 ◀── 부족 재료 ◀──────┘
```

- **식탁에 계획을 올리면 재고가 알아서 빠진다.** 예약 후 확정 방식으로, 사용자는 "조리 완료" 버튼을 누르지 않는다 (D-002).
- **부족한 재료는 장보기로 이어진다.** 계획 단위로 부족 항목을 모아 안내하고, "있는 만큼 사용 / 장보기 담기"를 선택한다 (D-010). 장보기 완료 시 재고에 자동 반영된다.
- **유통기한이 앱을 다시 열게 한다.** 재고를 구매 시점(배치) 단위로 관리하고 임박 알림을 보낸다 (D-003). 차감은 FEFO(유통기한 빠른 순).
- **입력 부담 최소화.** 식재료 마스터에서 선택만 하면 보관 장소·단위·유통기한이 자동 입력된다 (D-005). 단위는 식재료당 고정(개/g/ml)이며 계산은 기본 단위로만 한다 (D-004).

## 5. MVP 기능 범위 (D-009)

| 도메인 | MVP 범위 | 제외 (확장) |
| :---- | :---- | :---- |
| 냉장고 | 배치 단위 재고, 유통기한·임박 알림, 보관 장소(냉장/냉동/실온), 여러 식재료 일괄 등록 | 사진 인식 입력 |
| 요리 | 재료 목록만 등록 | 조리 순서, 사진, 소요 시간 |
| 식탁 | 날짜 + 끼니 + 레시피 연결, 부족 재료 일괄 안내 | 영양 정보, 칼로리 |
| 장보기 | 단일 장바구니, 완료 → 재고 자동 반영 | 마트별 분리, 가격 비교 |
| 계정 | 회원가입 시 개인 Household 자동 생성 (D-006) | 가족 공유 초대·권한 관리 |

## 6. 차별점

1. **무입력 재고 차감** — 계획만 세우면 재고가 맞아 들어간다. 경쟁 앱의 실패 지점인 "수동 기록 유지"를 구조적으로 제거.
2. **재방문 동기의 내장** — 유통기한 임박 알림이 기록이 아닌 행동(소진·장보기)으로 연결된다.
3. **4개 도메인의 순환** — 재고·레시피·계획·장보기 중 하나만 다루는 앱과 달리, 폐쇄 루프라 데이터가 쌓일수록 유용해진다.

## 7. 확장 로드맵

직접 입력 (MVP) → 사진 기반 품목 인식 · VLM (v1, D-007) → 영수증/주문내역 인식 (v2) → 쇼핑몰 연동·음성 입력

모든 입력 방식은 동일한 등록 경로(일괄 등록 화면 + 식재료 마스터)로 수렴한다. AI는 인식 → 사용자 검증 → 등록 순서를 강제하며 자동 확정하지 않는다.

## 8. 비즈니스 방향

- 무료 배포. 당면 목표는 수익화가 아니라 **실사용 검증**과 출시·운영 경험 확보.
- 수익 모델: 미정 (검증 후 검토)

## 9. 기술 개요 (D-011)

| 영역 | 선택 |
| :---- | :---- |
| 앱 | Flutter (iOS / Android 동시 출시) |
| 백엔드 | Spring Boot 3 + Kotlin + JPA |
| DB | PostgreSQL |
| 인프라 | AWS Lightsail + Docker + GitHub Actions CI/CD |
