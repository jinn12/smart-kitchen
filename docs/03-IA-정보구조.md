## 1. 구조 원칙 (D-012)

- 하단 탭은 순환 구조의 4개 도메인 그대로 **냉장고 / 요리 / 식탁 / 장보기** 4탭. 홈 탭은 두지 않는다.
- 시작 탭은 **냉장고**. 유통기한 푸시 알림의 착지점도 냉장고 탭 임박 섹션으로 통일한다.
- 끼니는 **아침 / 점심 / 저녁** 3종 (간식·야식은 확장 여지로만 남긴다).
- 설정·계정은 탭이 아닌 **상단 앱바 아이콘**으로 진입한다.

## 2. 전체 구조

```
Smart Kitchen
├─ 인증
│   ├─ 로그인
│   └─ 회원가입 (개인 Household 자동 생성, D-006)
│
├─ [탭1] 냉장고 ★시작 탭
│   ├─ 재고 목록 — 보관 장소 필터(전체/냉장/냉동/실온), 가용 수량 표시
│   │   └─ 상단: 유통기한 임박 섹션 (푸시 알림 착지점)
│   ├─ 식재료 상세 — 배치 목록(수량·유통기한·구매일), 변동 기록
│   └─ 식재료 일괄 등록 — 마스터 검색 → 여러 개 담기 → 기본값 확인 → 저장
│                          ★AI 사진 인식(확장)이 프리필로 재사용할 화면
│
├─ [탭2] 요리
│   ├─ 요리 목록 / 검색
│   ├─ 요리 상세 — 재료 목록, 재료별 가용 여부 표시
│   └─ 요리 등록/수정 — 재료는 마스터 검색으로 선택, 단위 자동 고정(D-004)
│
├─ [탭3] 식탁
│   ├─ 주간 캘린더 — 날짜×끼니 그리드, 오늘 포커스로 열림
│   ├─ 계획 등록 — 날짜+끼니 → 요리 선택 → 부족 재료 일괄 안내(D-010) → 등록(재고 예약)
│   └─ 계획 상세 — 수정/취소(예약 해제)
│
├─ [탭4] 장보기
│   ├─ 장보기 목록 — 단일 장바구니, 항목 체크, "두부 300g(1모)" 표시(D-004)
│   ├─ 항목 추가 — 수동 추가 + 부족 재료 담기 유입
│   └─ 구매 완료 → 재고 등록 — 체크된 항목의 수량·유통기한 확인 → 배치 생성 → 냉장고 반영
│
└─ 설정 (상단 아이콘)
    ├─ 계정 관리
    ├─ 알림 설정 (유통기한 임박 알림 on/off)
    ├─ 커스텀 식재료 관리
    └─ 앱 정보
```

## 3. 핵심 이동 흐름

**흐름 A. 식사 계획 (순환의 시작)** — 2026-08-21 구현에 맞춰 현행화
식탁 탭 → **요리 선택 → 날짜·끼니·인분** → 부족 재료 일괄 안내 화면(API-41 미리보기, 부족분별 "장보기 담기" 체크, D-010) → 등록 → 재고 예약(D-002). 사용자 추가 액션 없음. (요리를 먼저 고르는 순서로 변경 — "뭐 먹을지"가 출발점이므로)

**흐름 B. 장보기 완료 (순환의 마감)** — 현행화
장보기 탭 → 항목 체크 → "구매 완료" → 확인 다이얼로그(구매일=오늘, 유통기한=재료별 기본값 자동, D-005) → 배치 생성 → 냉장고 반영. 항목별 유통기한 개별 조정은 API 확장 필요 시 재검토(현재는 등록 후 냉장고 상세에서 수정).

**앱 공통 규칙 (2026-08-21)** — 순환 구조라 한 탭의 조작이 다른 탭의 숫자를 바꾼다. **탭 활성화 시 해당 탭을 재조회**한다(4탭 공통).

**흐름 C. 알림 재방문 (재방문 동기)**
푸시 "유통기한 임박 N건" → 냉장고 탭 임박 섹션 → 항목별 소진/폐기 처리 또는 상세 확인. (임박 재료 기반 요리 추천은 확장 지점)
