## 1. 표기 원칙

- 엔티티·코드·DB는 영문 명칭(엔티티 PascalCase, 컬럼 snake_case), 화면(UI)은 한국어 라벨을 사용한다 (D-008).
- 문서에서는 첫 등장 시 "요리(Recipe)" 형태로 병기하고 이후 한국어를 사용한다.
- **"식단"이라는 용어는 사용하지 않는다** — 다이어트 서비스의 인상을 피하기 위해 "식탁"을 사용한다 (D-008).

## 2. 핵심 도메인 용어

| 화면 라벨 | 영문 (엔티티) | 정의 | 관련 결정 |
| :---- | :---- | :---- | :---- |
| 가구 | Household | 데이터 소유의 기본 단위. 회원가입 시 개인 가구가 자동 생성되며, 모든 데이터는 가구에 귀속된다. 공유 UI는 MVP에 없다 | D-006 |
| 사용자 | User | 로그인 계정. 하나의 가구에 속한다 | D-006 |
| 식재료 | Ingredient | 재료의 표준 정의. 카테고리, 기본 보관 장소, 기본 유통기한, 단위 유형을 가진다 | D-005 |
| 식재료 마스터 | (system master) | 시스템이 제공하는 표준 식재료 목록(초기 300~500건). `is_custom = false` | D-005 |
| 커스텀 식재료 | (custom) | 마스터에 없어 사용자가 직접 추가한 식재료. `is_custom = true`, 소유 가구에서만 보인다 | D-005 |
| 냉장고 | Inventory | 가구가 보유한 식재료별 재고 집계. 명칭은 "냉장고"지만 냉장·냉동·실온 보관을 모두 포함한다 | D-003, D-008 |
| 배치 | InventoryItem | 구매 시점 단위의 재고 기록(수량·유통기한·구매일). 재고의 실제 단위이며, 냉장고 화면의 수량은 배치의 합계다 | D-003 |
| 요리 | Recipe | 재료 목록으로 구성된 요리 정의. MVP에서는 조리 순서·사진·소요 시간을 다루지 않는다 | D-009 |
| 재료 | RecipeIngredient | 요리에 필요한 식재료와 수량. 단위는 해당 식재료의 기본 단위로 고정된다 | D-004 |
| 식탁 | MealPlan | 날짜 + 끼니에 요리를 연결한 식사 계획. 등록 시 재고가 예약된다 | D-002, D-008 |
| 끼니 | MealType | 하루 안에서의 식사 구분. **구분 값(아침/점심/저녁/간식 등)은 미정 — IA 단계에서 확정** | — |
| 장보기 | ShoppingList | 구매할 식재료 목록. 단일 장바구니이며, 구매 완료 시 재고(배치)로 반영된다 | D-009 |
| 기록 | InventoryHistory | 재고 변동 이력(입고·차감·폐기 등) | D-008 |

## 3. 재고·수량 용어

| 용어 | 영문 | 정의 |
| :---- | :---- | :---- |
| 실물 보유량 | quantity | 실제 보유 중인 총량. 배치 합계와 일치한다 |
| 예약 수량 | reserved_quantity | 식탁 계획이 잡아둔 수량. 아직 실물은 차감되지 않은 상태 (D-002) |
| 가용 수량 | available | `quantity - reserved_quantity`. 화면 기본 표시와 부족 판단의 기준 (D-002) |
| 예약 | reserve | 식탁 등록 시 필요 수량을 가용에서 잡아두는 것. 사용자 액션 불필요 (D-002) |
| 확정 | confirm | 계획 날짜 경과 후 배치 작업이 예약분을 실제 차감으로 전환하는 것. 이 시점에 FEFO로 배치가 지정된다 (D-002, D-003) |
| FEFO | First-Expired-First-Out | 유통기한이 빠른 배치부터 차감하는 순서 규칙 (D-003) |
| 부족 | shortage | 특정 계획에 대해 가용 수량 < 필요 수량인 상태. 계획 단위로 모아 안내한다 (D-010) |

## 4. 단위·속성 용어

| 용어 | 영문 | 정의 |
| :---- | :---- | :---- |
| 단위 유형 | unit_type | `COUNT(개)` / `WEIGHT(g)` / `VOLUME(ml)` 3종. 식재료당 1개로 고정 (D-004) |
| 기본 단위 | base_unit | 모든 수량 계산에 사용하는 단위. 포장 단위로는 계산하지 않는다 (D-004) |
| 포장 단위 | package_name / package_size | 표시 전용 단위. 예: 두부 1모 = 300g (D-004) |
| 보관 장소 | StorageLocation | 냉장 / 냉동 / 실온. 냉장고 화면 내 구분 기준 (D-008) |
| 정량 관리 제외 | is_trackable = false | 소금·후추·식용유 등 정량 관리가 무의미한 품목. 재고 차감 대상에서 제외 (D-004) |
| 기본 유통기한 | default_shelf_life | 마스터가 제안하는 유통기한 일수. 등록 시 자동 제안, 사용자 수정 가능 (D-005, D-007) |
| 유통기한 | expiry_date | 배치별 소비 기한 날짜. **임박 기준(며칠 전 알림)은 미정 — 정책 확정 필요** | 

## 5. 미정 용어 (후속 문서에서 확정)

| 항목 | 내용 | 확정 시점 |
| :---- | :---- | :---- |
| 끼니 구분 값 | 아침/점심/저녁만 둘지, 간식·야식을 포함할지 | IA |
| 유통기한 임박 기준 | 알림을 며칠 전에 보낼지, 카테고리별로 다르게 할지 | 도메인 모델 |
| 하단 탭 라벨 | "식탁" vs "식사"/"오늘" — D-008 유보 사항 | 사용자 테스트 후 |
